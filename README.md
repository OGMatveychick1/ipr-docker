# Счетчик в Docker

Готовое приложение со счетчиком запускается через Docker Compose. Работают два сервиса: `app` принимает HTTP-запросы, `redis` хранит счетчик. Код приложения не менялся.

## Запуск

Нужен установленный и запущенный Docker с Compose. Все команды выполняются из папки проекта.

Первый запуск в PowerShell:

```powershell
Copy-Item .env.example .env
docker compose up -d --build --wait --wait-timeout 60
```

В Bash вместо первой команды используется `cp .env.example .env`.

Открывается по адресу: http://127.0.0.1:8080/

Остановка и удаление контейнеров:

```powershell
docker compose down
```

Повторный запуск:

```powershell
docker compose up -d --wait --wait-timeout 60
```

## Настройки

В `.env` можно изменить:

- `APP_PORT` — порт на компьютере. В примере это `8080`.
- `GREETING` — приветствие приложения. В примере это `Hello-from-my-Compose`.

После изменения настроек нужно выполнить `docker compose up -d`. Если изменить порт, в адресе страницы тоже нужно указать новый.

Приложение внутри контейнера работает на порту `8000`. На компьютер опубликован только его порт, доступный по `127.0.0.1`. Redis доступен приложению внутри сети Compose по адресу `redis://redis:6379/0`.

## Как это устроено

- `Dockerfile` описывает сборку образа: Python, установка зависимостей, копирование и запуск `app.py`.
- `compose.yaml` задает два сервиса, сеть, настройки и хранилище.
- `STORAGE=redis` переключает приложение на Redis, `REDIS_URL` задает адрес подключения.
- `depends_on` ждет готовности Redis перед запуском приложения. У обоих сервисов есть healthcheck.
- Redis записывает изменения на диск с помощью `--appendonly yes`. Его каталог `/data` подключен к именованному volume `redis_data`.

После `docker compose down` контейнеры удаляются, но данные остаются в volume. Команда `docker compose down -v` удаляет и хранилище с данными.

У приложения выставлены ограничения:

- пользователь и группа `10001:10001`, без прав root;
- файловая система только для чтения;
- не больше 256 MiB памяти;
- процессорное время в пределах одного ядра.

## Проверка вручную

Посмотреть счетчик:

```powershell
curl.exe -fsS http://127.0.0.1:8080/
```

Увеличить его на 1:

```powershell
curl.exe -fsS -X POST http://127.0.0.1:8080/increment
```

Посмотреть состояние сервисов и логи:

```powershell
docker compose ps
docker compose logs app redis
```

Для проверки сохранения данных счетчик увеличен до 3. После `docker compose down` и повторного запуска значение осталось 3, а hostname приложения изменился.

Проверка отключения Redis:

```powershell
docker compose stop redis
curl.exe -i -sS --max-time 30 http://127.0.0.1:8080/healthz
curl.exe -i -sS --max-time 30 http://127.0.0.1:8080/readyz
curl.exe -i -sS --max-time 30 -X POST http://127.0.0.1:8080/increment
docker compose start redis
```

При отключенном Redis получены ответы:

| Запрос | Код |
| --- | --- |
| `GET /healthz` | 200 |
| `GET /readyz` | 503 |
| `POST /increment` | 503 |

После запуска Redis и восстановления готовности счетчик остался 3, следующий POST вернул 4. Приложение при этом не перезапускалось.

## Автоматическая проверка

Скрипт `scripts/check.sh` требует Bash, Docker с Compose и curl. Python и tar для проверок используются внутри контейнеров, отдельно устанавливать их на компьютер не нужно.

Запуск в Bash:

```bash
./scripts/check.sh
```

Запуск из PowerShell через Git Bash:

```powershell
& "C:\Program Files\Git\bin\bash.exe" ./scripts/check.sh
```

Скрипт создает отдельный проект с уникальным именем, пустым хранилищем и свободным портом. Проверяет значения 0, 1, 2, 3, пересоздает только приложение и проверяет сохранение 3. Затем проверяет отключение Redis, восстановление без перезапуска приложения и увеличение до 4.

После проверок останавливает приложение и Redis, сохраняет весь каталог данных в архив `backups/<имя-тестового-проекта>.tar` и проверяет читаемость архива. В архиве сохраняются структура каталогов и сведения о правах доступа.

При завершении через `trap` удаляются только ресурсы тестового проекта, включая его volume. Архив остается на компьютере. У запросов и ожидания готовности есть тайм-ауты. При ошибке выводятся этап и последние логи, скрипт возвращает ненулевой код.

Два запуска подряд прошли успешно, оба завершились с кодом 0. Вывод сохранен в [check-run-1.txt](check-run-1.txt) и [check-run-2.txt](check-run-2.txt).

Логи первоначального запуска одного контейнера сохранены в [logs.txt](logs.txt). Сохранение данных сначала проверено с SQLite, затем с Redis. В текущем Compose используется Redis.
